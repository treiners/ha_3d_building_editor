# Move modes (Phase 1)

A **Move mode** switch in the sidebar (below Undo/Redo) decides what happens when a room is dragged. The default is **Free**, which is exactly the behaviour the editor had before. The mode is a view setting: it is not saved in the graph.

| Mode | Behaviour |
|---|---|
| **Free** | Unchanged: the room moves on its own, walls detach, connectors re-align (wall-alignment groups still move together). |
| **Slide along walls** | Attached walls are kept. Across an attached wall the room cannot move; along it the room slides within the joint's slide range, with the opening staying where it is whenever it still fits. |
| **Slide + pull neighbours** | Like Slide, but moving across a wall, or beyond the slide range, pulls the neighbour along (and its neighbours in turn), as little as possible. Where minimal pulls contradict each other around a loop of rooms, the whole attached group moves rigidly. |

**Alt + drag** (Slide and Slide + pull) moves the room freely and detaches on purpose: every joint that was attached and is no longer touching afterwards is stored as `detached` in `graph.joints`, so it is not re-attached by later drags. Undo restores it.

Rules shared by both new modes
- Locked rooms never move. A lock here means a *position* lock (see `V2.15-WALLS.md`; the old single `locked` flag counts as both). If a locked room stands in the way, the move stops at the last possible step and the status line says why.
- **Block overlaps** (checkbox, default on): a move that would create a new overlap stops at contact. The drag is swept step by step from the start, so a room cannot tunnel through another one. Free mode may still overlap.
- Only joints that were attached when the drag started are protected. Broken or detached walls do not restrain anything.
- The move is planned from the graph as it was at the start of the drag, so dragging back returns to the exact start position.
- Openings (door/passage points) stay in place while a room slides (when both rooms move together along the wall the opening travels with them); if they would leave the shared part they are pushed just inside. Both connectors of a pair always get the same world position, so the pair stays green.
- **Whole floor plan** (`blockWholePlan`, on in the editor): a move that would shift the whole floor plan, defined as the largest group of rooms connected by attached walls (unattached rooms and smaller separate groups do not count), is stopped at the last step before that, with the message "Stopped: this move would shift every room". A smaller separate group may still move as a whole. The hidden `Outside` room does not count.
- Wall-alignment groups are only honoured in Free mode for now.
- With a room selected, its attached walls are drawn as teal segments with a slide arrow (not in Free mode, not in Gap view).

Code: `src/moves.ts` (`planMove`, pure, embedded in the HTML like `mapLayout` and `deriveJoints`), hooks in `src/editor.ts` (`applyPlan`, `detachBroken`, `jointOverlay`, the `move-mode` select).

Tests: `test/moves.test.ts` (hand-computed slide ranges, pull cases, locked rooms, rigid fallback around loops, and 500 random drags on the reference home checking that attached walls are never lost and locked rooms never move) and the drag scenarios in `scripts/browser-smoke.mjs`.

## Free mode and connectors (changed after user feedback)
While a room is dragged in **Free** mode (and with Alt+drag), the connector pairs that were aligned (green) when the drag started stay aligned, without the old per-move averaging that made the drag jump: each pair sits at its start position, clamped into the shared part of the two walls (5 cm inside each end), recomputed from the start snapshot on every move (so there is no drift and dragging back returns exactly). If the walls stop touching, both connectors go back to their start offsets and move with their rooms. Pairs that were already apart are never touched. Corner resize in Free mode is unchanged.

**Dragging around obstacles**: for a room without attached walls (nothing else has to move) the Slide modes sweep from the room's current position towards the pointer instead of from the start of the drag, and slide along a room that blocks the way. A free room can therefore be dragged around another room in one continuous move; a room with attached walls is still planned from the start of the drag (exact return on dragging back).

**Connector drag**: a connector that has a partner and touches it can only be dragged within the shared part of the two walls (5 cm inside each end), whichever of the two connectors is grabbed, so the pair no longer separates by accident.
