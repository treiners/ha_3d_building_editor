# Connector width, door type and Close gaps

Both additions are optional and additive: files without the new fields behave exactly as before.

## Connector `width` and `doorType`
- `width` (metres, optional) on a connector is the opening width. Without it the default by type applies (door 0.9, open passage 1.2, window 1.2). A relationship uses the larger of its two connectors.
- Everything that used the constants now reads the width: `deriveJoints` (`openingWidth`, `narrow`, slide range), the wall solver (opening cut-off, shared part kept along the wall), `mapLayout` (a relationship counts as satisfied when the shared wall is at least the width) and `connectRooms` / `addRoom` (the shared wall must be at least width + 0.1 m).
- `doorType` (`hinged-left`, `hinged-right`, `sliding`, `pocket`) is metadata only, for later 3D / Home Assistant output. The layout solver ignores it, and there is no width default per door type.
- UI: "width m" and "door type" fields under the new-room type in the Rooms card (used by *Add room* and *Connect*), and a width box per connector in the room panel (sets both ends of the pair, one undo step; empty = default).
- An L-shaped room can be approximated now by two rectangles joined with an open passage whose `width` is large, as long as the shared wall is at least width + 0.1 m. A dedicated full-width opening type is not implemented.

## Close gaps (`planClose`, `src/walls.ts`)
Button *Close gaps* in the sidebar. Every relationship that is broken only by a positive gap (walls face each other with a shared part) is closed by dragging one wall to contact with the wall solver: room A's wall first, room B's if that is blocked. Locks, sizes, doors and overlaps are honoured as for a manual wall drag; a gap that cannot be closed is reported ("N not closed (relationship: reason)") and left alone. Connectors are re-aligned afterwards. One undo step.

## Selecting a connector, width bars, ghost preview
- Clicking a connector (without dragging) selects it: its own card appears above the room panel with type (door / open passage / window), width, door type and Remove; type and door type are applied to both ends of the pair, one undo step. Selecting a room, wall or room clears it.
- Tickbox *Show connector widths* (off by default) draws every opening as a bar of its width (the larger width of the pair) centred on the connector point, green / red / orange like the points. The bars make the limited slide range visible; they are pointer-transparent.
- Ghost preview while dragging in Slide modes, the wall tool and corner handles: a dashed outline shows where the pointer wanted the room / wall / corner, drawn only when the result differs, and every neighbour that was pushed or resized is tinted orange. The stop reason is still shown in the status line. Free mode is unchanged (no preview).

## Fit to neighbours (`planFit`, `src/walls.ts`)
Button *Fit to neighbours* acts on exactly ONE selected room, tolerance 0.3 m. Each of its four walls (order left, right, top, bottom, each result carried into the next) goes to the nearest correction within the tolerance, using the wall solver (locks, sizes, doors and overlaps honoured, like a manual wall drag):
1. contact with the nearest facing neighbour (related or not): a gap is closed, a small overlap is pulled back;
2. otherwise the same level as a neighbour that touches the room beside that wall (collinear snap).
A wall that cannot move is reported ("N not moved (side: reason)"). One undo step; connectors are re-aligned afterwards. A whole-plan variant and a settable tolerance are not implemented.

## Connectors stay inside the wall
The opening point keeps half the opening width (larger width of the pair, at least 0.05 m) from both wall ends (`mg`, used by `norm` and `setWorld`), and dragging a connector is limited to the shared wall part with that margin (`portTarget`). Changing a connector's width or type re-clamps both ends. The selected-room border is drawn as thin as the walls (0.05).

## Building defaults, door swing, window heights
All optional; files without them behave as before. Walls are still drawn as zero-thickness lines: the building values are metadata for later 3D / Home Assistant output.
- `graph.buildingDefaults` `{ wallThickness 0.16, wallHeight 2.4, floorThickness 0.12 }` (m). Card *Building* in the sidebar (clamped: thickness 0.05-0.6, wall height 2-5); *Save graph* always writes the block, one undo step per edit.
- Door spec on a connector: `door: { hinge: "left" | "right", swing: "inward" | "outward", openAngle: 85 }` (defaults left / inward / 85; the editor keeps them implicit, *Save graph* writes them out via `fillDefaults`). Hinge is seen from inside the connector's own room facing the wall, `inward` = swings into that room. The partner connector of the same relationship is kept as the mirror image (hinge and swing flipped, same angle), so both describe one physical door. `doorType` is now `hinged` | `sliding` | `pocket`; swing controls only exist for hinged doors (an old `hinged-left` / `hinged-right` value is still read as hinged with that hinge).
- Swing symbol (`doorGeometry` in `src/door.ts`, pure and embedded): drawn only while a hinged door connector is selected: door leaf, swing sector and a blue handle at the leaf end. Dragging the handle sets the open angle (10-180, steps of 5, `doorAngle`); the card has hinge / swing / angle fields too; the swing options name the rooms ("into Kitchen" / "into Hall").
- Window spec: `window: { type "fixed", sillHeight 0.8, headHeight 2.1, frameDepth 0.08 }` (copied to the partner; *Save graph* writes the defaults). The card edits sill and head height; head is kept between sill + 0.2 and the wall height, sill between 0 and wall height - 0.2. Type and frame depth only keep their defaults for now.
