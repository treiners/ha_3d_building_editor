# Objects: appliances and furniture (phase 1 of 6)

An **object** is a physical thing with a footprint in a room or area (refrigerator, oven, washing machine, sofa, bed). It gives the visualisation context (a box model) and, from phase 5, it can be the host of entities (a door contact on the fridge). The saved format is described in `FILE-FORMAT.md` (generated); this note says what exists and what comes next.

## Decisions
- Appliances and furniture are both in the catalogue; `category` lets a reader hide furniture (it adds clutter in Home Assistant).
- `position` is the centre of the footprint, relative to the host's top-left corner; `facingDegrees` is the direction of the front (0 = up, clockwise), the same convention as entities.
- Built-in catalogue in code (`objectCatalog`), optional custom types in the file (`objectTypes`).
- The schema version stays 3.0: every new field is optional.

## Phase 1 (done): model, no UI
- `src/objects.ts` (pure, embedded, typed without `any`): `objectCatalog`, `objectDefs`, `objectFootprint`, `objectHost`, `objectHostAt`, `objectClamp`, `addObject`, `moveObject` (changes room when the point is in another one), `updateObject` (checked numbers, facing normalised), `removeObject` (also removes entities with that `objectId`), `validateObjects`, `fillObjectDefaults`.
- Problems found by `validateObjects`: `unknown-type`, `no-host`, `outside`, `overlap` (same height range, separating axis test), `blocks-door` (in front of a door or open passage), `too-high`. The contract reports them as warnings (`object-<code>`); `no-host` is the error `dangling-object`, repeated ids are `duplicate-object`.
- Floors: objects follow their room between floors (`floorsSplit`, `floorsSwitch`, `floorsMerge` with unique ids); objects of areas stay with the graph. A copied floor starts without objects, like entities.
- `removeRoom` / `removeArea` delete their objects and the entities on them. `savedGraph` writes the defaults of every object.
- Tests: `test/objects.test.ts` (hand-computed geometry and rules), `test/objects-integration.test.ts` (floors, deletion, save, contract), plus the embed, page-names and format-document tests that pick the new code up.

## Phase 2 (done): Objects mode
- Fourth app mode `Objects` (switch next to Entities); `src/editor-objects.ts` (`objectsCss`, `objSideHtml`, `objectsJs`, hooked in `editor.ts`, `editor-shell.ts`, `editor-css.ts`; only the app switch and one status message touch `editor-entities.ts`). Rooms are read-only (the core pointerdown returns unless `appMode==='plan'`).
- Palette (appliances / furniture, from `objectDefs`, so custom types appear), click in a room or area to place (grid = entity grid step, Alt = free, Shift = keep placing, Esc cancels), drag to move (re-hosts between rooms / areas), round handle rotates (15 degree steps, Alt = free), `R` / `Shift+R` rotate 90 degrees, arrows nudge, Delete removes (also entities on it), inspector (name, type, host, x / y, width, depth, height, elevation, facing, warnings from `validateObjects`).
- Drawing: box footprint with a thick front edge and label, above the rooms in every mode (clickable only in Objects mode); red dashed outline for objects with a validation problem. One undo step per finished gesture.
- Not covered: automated browser smoke scenario (add one to `scripts/browser-smoke*.mjs`).

## Phase 3 (done): resize, snap, clearance, copy / paste, list
- Resize: four edge handles on the selected object (width left / right, depth front / back, 0.05 m steps, Alt = free, the opposite edge stays put).
- Snap to walls (`objectSnap`, pure): an edge within 0.15 m of a wall of the host snaps to it while moving and placing; checkbox *Snap to walls* (default on), Alt = free.
- Clearance zones (`objectClearance`, pure): the free zone in front (`clearance` of the type) is drawn for the selected object, or for all with *Show clearance zones*. Drawing only: it is not validated.
- Copy / paste: Ctrl+C / Ctrl+V (pastes at the pointer, keeps size, name and category). List tab with filters by room / area and type; a row selects the object, `!` marks a validation problem (tooltip).
- The inspector is a floating box on the canvas (`#obj-inspector` in `editor-boxes.ts`), like the room, stair and entity boxes.
- Open passages are free: only doors produce `blocks-door`.

## Phase 4 (done): definition of types
- **Types** tab in Objects mode: all types (built-in and custom) in a table (`custom` / `edited` marks); edit name, category, width, depth, height, elevation, clearance; *New type*, *Copy as new type*, *Delete type* (custom) or *Reset to default* (built-in override).
- Pure, embedded, tested (`test/objects-types.test.ts`): `addObjectType` (id = slug of the name, unique against built-ins), `updateObjectType` (checked numbers; editing a built-in writes an override with the same id into `objectTypes`), `removeObjectType` (refused while objects on any floor use a custom type; removing the override of a built-in resets it; `objectTypes` is dropped when empty).
- Objects without their own size follow the type defaults live; *Save graph* writes the sizes explicitly (`fillObjectDefaults`), so a saved object keeps its size when the type is edited later.
- Smoke scenario for the whole mode: `scripts/browser-smoke-objects.mjs`.

## Phase 5 (done): entities on objects
- An entity with `objectId` (instead of `roomId` / `areaId` / `connectorId`; exactly one of the four) sits ON an object, e.g. a door contact or temperature sensor on the fridge, a leak sensor on the washing machine.
- `position` = metres from the object's CENTRE in the object's own frame (x along its width, y along its depth), so the entity follows the object when it is moved or rotated; `height` defaults to the top of the object. Only catalogue types with `onObject` fit: light, motion sensor, camera, environment sensor, water-leak sensor, door contact (one per object).
- Objects mode: the inspector lists the entities of the object, offers suggested types (`entitySuggestions`, keyword based so custom types work) and removes them. Entities mode: they are drawn, listed (parent = the object) and can be dragged / nudged inside the footprint (clamped, never re-parented); Diagnostics: `orphan` (missing object), `outside-object`, `type-mismatch`.
- Pure, embedded, tested (`test/entities-objects.test.ts`): `entityObjectFrame`, `entitySuggestions`, `objectId` support in `addEntity`, `moveEntity`, `updateEntity`, `entityWorld`, `validateEntities`, `coverageHints` (a motion sensor on a sofa counts for the room). Deleting an object or its room removes its entities (already in `removeObject` / `removeRoom`).
- Floors: an entity on an object belongs to the object's floor (split / switch); merging renames clashing object ids (`o-f2`) and remaps `objectId`.
- Not covered: multi-select move / copy / paste of object entities (they are skipped), the `objectId` entry in the generated file-format description.

## Phase 6 (done): example house, file-format description, notes for the visualisation
- **Example house:** `examples/objects-example.ts` (`buildObjectsExample`) builds it from the reference home: rooms are mapped, appliances and furniture stand against walls (snapped, front into the room), a custom type (`aquarium`) is added, sensors sit on the objects (fridge: door contact and environment sensor, washing machine / dishwasher: leak sensor, sofa / bed: motion sensor). Anything that would not validate is dropped, so the result is clean; `test/objects-example.test.ts` checks this. Write the files with `node dist/examples/make-objects-example.js ../shared/reference-home-connectors.json examples/house-with-objects.json examples/house-with-objects.html` (after `npm run build`) and load the JSON in the editor as a testbed.
- **File format:** `docs/FILE-FORMAT.md` (generated, `npm run build && npm run docs:format`) describes objects, `objectTypes`, the entity anchor `objectId`, the "On objects" column of the entity types and the new checks.
- **For the 3D visualisation** (everything is in metres, x right, y down, one frame for all floors):
  - Object footprint: a box `width` (across the front) x `depth` (front to back) centred at `host corner + position`, turned by `facingDegrees` (clockwise from up, 0 = front points up the plan, 90 = right). Local axes: width along (cos a, sin a), depth along (-sin a, cos a); the front is at -depth/2.
  - Vertical: from `elevation` (underside above the floor, 0 for floor-standing) to `elevation + height`, on top of the floor surface of the host's floor (`floors[].elevation`). `category` `furniture` may be hidden; `clearance` of the type is the free zone in front (not part of the object).
  - Types: built-in table in FILE-FORMAT.md, overridden or extended by `objectTypes`; sizes are written explicitly on every object, so a reader needs no catalogue.
  - Entity on an object: world point = object centre + R(a) * `position` (R = the same rotation), at `height` above the floor. Entities keep their HA binding in `haEntityId`.
  - Ignore what you do not know: every object field after `id`, `type`, `position` is optional.
