# Floors and stairs (3.1)

Several storeys in ONE coordinate frame, so alignment between floors needs no extra numbers: all floors share the same x / y, the floor below is shown as a dashed ghost, and *Match below* snaps walls to it.

## Saved format (all fields optional, files without `floors` are single-floor and unchanged)
- `graph.floors = [{ "id": "floor-1", "name": "Floor 1", "height": 2.4, "elevation": 0 }, ...]`, bottom to top.
  - `height` = storey height in metres (wall height of that floor). Optional in the editor (empty = `buildingDefaults.wallHeight`), always written on save.
  - `elevation` = DERIVED, written on save, ignored on load: height of the floor surface above the ground = 0 for the first floor, then the sum of (`height` + `buildingDefaults.floorThickness`) of the floors below. Example: heights 2.4 / 2.4, floor thickness 0.12 -> elevations 0 and 2.52.
- `room.floor` = floor id (absent = first floor). Connectors, relationships (within one floor), wall alignments and entities follow their rooms. Outside areas (Site mode) are shared by all floors.
- `graph.stairs = [{ "id": "stairs-1", "name": "Stairs 1", "lower": "floor-1", "upper": "floor-2", "x": 3.0, "y": 1.2, "length": 3.0, "width": 1.0, "direction": "right", "fromRoom": "hall", "toRoom": "landing" }]` (see Stairs below).
- On save, ids are made unique across floors (a clash gets the floor id as suffix, also for connectors, relationships and the entities that point at them). *Save graph* moves the top-left corner of the house to (0,0) for all floors together (rooms, areas and stairs).

## Stairs
A stair is a rectangle seen from above that connects two floors lying directly above each other (`upper` = the floor above `lower`).
- `x`, `y` = top-left corner of the rectangle (plan metres, same frame for all floors). `length` runs along `direction`, `width` across it. Length 0.6 - 12 m, width 0.5 - 4 m.
- `direction` = the way the stair climbs on the plan: `right` (+x), `left` (-x), `up` (-y, north on screen), `down` (+y).
- It is drawn on BOTH floors with treads and a **thick bar where the stair lands on that floor**: on the lower floor at the start (the side opposite to `direction`), on the upper floor at the end (the side `direction` points to). Example: direction `right` = bar on the left in the room below, bar on the right in the room above.
- `fromRoom` / `toRoom` are DERIVED on save, ignored on load: the room that contains the middle of the bar on the lower / upper floor (null = the end is not inside a room; the contract check warns about it).
- Editor: `+ Stair` (floor bar, needs two floors) adds one in the middle of the view between the current floor and the next one (on the top floor: the one below). Click selects, drag moves (grid snap, Floor plan mode only), the four corner handles of the selected stair resize it (the opposite corner stays put, same limits as the fields, grid snap), the panel at the top right sets name, length, width and the direction arrows, and deletes it. Every change is one undo step. In Site and Entities mode stairs are shown but cannot be touched.
- Files from the 3.1 development build with room-pair stairs (`lower` / `upper` = `{ floor, room }`) are converted on load to a stair covering the lower room, climbing to the right.

## Editor
- **Tabs** at the top-left of the canvas (all modes): click or **PageUp / PageDown** = switch floor, double-click = rename, `+` = new empty floor above (one placeholder room at the plan's top-left), `Copy` = new floor above as a copy of the current one (ids get the new floor id as suffix, entities and stairs are not copied, the height is inherited), `x` = delete the current floor with its stairs (confirms). `h [ ] m` = storey height of this floor. Add / delete / rename / height are one undo step each; switching floors is not. **Fit** (the toolbar button) fits all floors, so the view does not jump when you switch.
- **Ghost:** the rooms of the floor directly below (without `Outside`) are drawn dashed and pale under the current floor; they cannot be clicked.
- **See-through (key T):** draws the current floor 80 percent transparent (fill at 20 percent) and strengthens the ghost, so the floor below is clearly visible. Needs a floor below; view setting only.
- **Match below:** (Floor plan mode) every wall of the current floor that is within 0.3 m of a parallel ghost wall (sharing at least 0.3 m of length) is moved onto it with the wall solver (`planWall`: locks, doors, neighbours and the *Block overlaps* / glue settings are honoured; walls that cannot move are counted in the status line). One undo step.
- Entities are placed per floor in Entities mode: switch the tab, then place.

## Contract check and the saved file
`savedGraph` (src/save.ts) is the exact file that *Save graph* writes. Before downloading, `checkContract` (src/contract.ts) runs over it and shows a panel when there is anything to report (errors: duplicate ids, dangling connectors / alignments, rooms without layout, rooms on unknown floors, invalid relationships, stairs between floors that are not directly above each other or without size; warnings: relationships that are not green, stair ends outside every room, entity / area problems). A clean file is saved at once, otherwise: Save anyway or Cancel. `test/roundtrip.test.ts` guarantees that load -> save -> load -> save gives the same file (single floor and two floors with a stair).

## Image underlay
Bottom-left of the canvas: `Image` loads a floor-plan photo / scan (png, jpg, ...; for a PDF export the page as an image first), `Scale` = click two points of known distance and enter it in metres, `Move` = drag the image (click again to edit the plan), opacity slider, `x` removes it. One image per floor, browser only: it is never saved and not part of undo.

## How it works (so the rest of the editor is untouched)
While editing, `g.rooms / relationships / wallAlignments / entityPlacements` hold ONLY the current floor, so every planner, tool and mode works as before. The other floors sit in the working-only key `g._fl = { cur, data }` inside the graph (undo / redo restore it) and are never saved. `src/floors.ts` (pure, embedded like the other modules) converts: `floorsSplit` (saved -> working), `floorsMerge` (working -> saved), `floorsSwitch`, `floorsAdd`, `floorsRemove`, `floorsRename`, `floorsGhost`, `floorsFill` (heights, elevations). `src/stairs.ts`: `stairRect`, `stairBar`, `stairsVisible`, `stairsAdd`, `stairsUpdate`, `stairsRemove`, `stairsHost`, `stairsFill`; `g.stairs` is global (not stashed per floor). UI: `src/editor-floors.ts`, `src/editor-stairs.ts`.
