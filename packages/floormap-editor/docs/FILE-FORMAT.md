# Floor-plan file format

_Generated by `npm run docs:format` from `src/file-format-doc.ts` (do not edit by hand; a test compares it with the code)._

One JSON file describes one house: rooms with their connectors, how rooms are connected, where everything is, and the things that
are added on top (floors, stairs, outside areas, sensors and other entities). The editor reads older files and writes every default
explicitly, so a saved file is complete.

## Conventions

- Lengths are **metres**. **x points right, y points down** (screen orientation). All floors share one coordinate frame.
- On save the origin is moved to the top-left corner of the house and coordinates are rounded.
- Angles are **degrees**. `facingDegrees` is clockwise from up (north on the plan): 0 = up, 90 = right. `northDegrees` is how far the plan's up is turned away from true north.
- Ids are short slugs, unique within their kind (rooms, connectors, relationships, floors, stairs, areas, entities).
- Every field after the original core is optional: a reader may ignore fields it does not know.

## Versions

- `2.14`: the core (`rooms`, `relationships`, `wallAlignments`, `joints`, `buildingDefaults`).
- `3.0`: the same core plus the optional parts `floors`, `stairs`, `areas`, `entityPlacements`, `entitySettings`, `northDegrees`. Nothing of the core changed.
- Objects (`objects`, `objectTypes`) and the entity anchor `objectId` are further optional parts of the same format (editor 3.1); a reader that does not know them can ignore them.
- The editor currently writes `schemaVersion: "3.0"` and reads both.

## Rooms

`{ id, name, type, sizeCategory, connectors[], layout, outline?, floor? }`

- `sizeCategory`: `small` (3 x 2 m), `medium` (4 x 3), `large` (6 x 4): the default size when a room has no `layout` yet.
- `layout`: `{ x, y, width, height }`, top-left corner and size. Optional lock flags: `positionLocked` (corner fixed), `sizeLocked` (size fixed); old files use `locked: true` for both.
- `floor`: id of the floor the room is on; absent = the first floor.
- `elevation` (optional, metres, 0..10, default 0): height of the room floor above the floor baseline of its floor. `wallHeight` (optional): height of all walls of the room. `wallHeights` (optional) `{ top, right, bottom, left }`: single walls. A wall height is resolved in this order: `wallHeights[side]`, `wallHeight`, `height` of the room's floor, `buildingDefaults.wallHeight`, 2.4 m. Where two rooms share a wall the editor (Walls mode) sets the same height on both sides, because it is one physical wall; if a file has two values, a reader may use the larger one and the check warns (`height-shared-wall-height`). A room with a shape has one height per side for all wall segments on that side.
- `outline`: optional shape for a room that is not a rectangle (L, U, T, bays): the corners `[[x, y], ...]` in metres from the top-left corner of `layout`, clockwise on the plan (x right, y down), 90 degree corners only, starting at the top-left-most corner, no collinear corners and no holes. `layout` stays the bounding box (the outline spans exactly `width` x `height` from (0, 0)), so a reader that ignores `outline` sees a rectangle. A room with an outline is size-locked. Absent = rectangle. A connector keeps its `side` (the way the wall faces) and `offset`, measured from the bounding box edge: the wall it sits on is the one facing that side at that offset. Where two walls facing the same way cover that offset (the outer wall and the notch wall of an L), the optional connector field `wallAt` (the wall's coordinate in metres from the bounding box origin) names the one it is on; without it the outermost wall is meant.

## Connectors

`{ id, roomId, side, type, offset, width, wallAt?, doorType?, glazing?, door?, window? }`, listed in the room they belong to.

- `side`: `top`, `right`, `bottom`, `left` (the wall of the room). Only opposite sides can share a wall.
- `offset`: metres from the start of the wall (left end for top / bottom walls, top end for left / right walls), at least 0.05 m from either end. `position` (0..1) is the legacy form of the same value and may still appear in old files.
- `type`: `door`, `open-passage` or `window`.
- `width` default by type: door 0.9 m, open passage 1.2 m, window 1.2 m.
- `doorType`: values starting with `hinged` are hinged doors. A hinged door has `door: { hinge, swing, openAngle }`: `hinge` is `left` or `right`, `swing` is `inward` or `outward`, `openAngle` in degrees.
  Defaults: hinge `left`, swing `inward`, openAngle 85. The partner connector of a pair is the mirror image.
- A window has `window: { type, sillHeight, headHeight, frameDepth }`, defaults `fixed`, 0.8, 2.1, 0.08 (metres above the floor / metres).
- Window `type`: `fixed`, `slide-vertical` (sliding up / down), `slide-horizontal` (sliding left / right), `tilt` (tilts in from the top), `hinged` (turns like a door) or `tilt-turn` (tilts and turns). `hinge` (`left` | `right`, seen from the room of the connector) and `swing` (`inward` | `outward`) apply to `hinged` and `tilt-turn` (default left, inward; always written on save); `slide` (`start` | `end`) is the direction in which one sash slides over the other for `slide-horizontal` (default start; always written on save). The head height is limited by the height of the wall the window sits in.
- Door `glazing` (optional): `glass` when the door leaf is glass, for example a glass sliding door (`doorType` `sliding`); absent = `solid`. Both connectors of a pair carry the same value.
- Door `door.tilt` (optional, `true`): a hinged door that also tilts (tilt and turn). Door `door.slide` (`start` | `end`, always written on save for sliding and pocket doors; a missing value means `start`): the direction in which a `sliding` or `pocket` door opens (one half slides over the other half); the width of both follows this movement. These doors carry no `hinge`, `swing` or `openAngle`. The editor shows the direction as left / right, seen from the room of the selected connector, facing the wall. `start` / `end` = towards the smaller / larger x (top and bottom walls) or y (left and right walls); both connectors of a pair carry the same value.

## Relationships

`{ id, connectorA, connectorB, importance }`: two connectors on opposite walls of two rooms that touch. The opening sits where the two connectors are (they are within 0.2 m of each other when the pair is consistent).

- `importance`: `required` relationships weigh most when the mapper places rooms (1 against 0.4); any other value counts less.

## Floors and stairs

- `floors`: `[{ id, name, height?, elevation? }]`. `height` = floor to ceiling, `elevation` = height of the floor surface above the lowest floor; both are filled on save.
- `stairs`: `[{ id, name?, lower, upper, x, y, length, width, direction, fromRoom?, toRoom? }]`. `lower` / `upper` are floor ids of two floors directly above each other. `x, y` is the top-left corner of the stair rectangle, `length` runs along `direction` (`right`, `left`, `up`, `down` = the way the stair climbs on the plan), `width` across it.
  The landing bar is at the start of the stair on the lower floor and at the end on the upper floor. `fromRoom` / `toRoom` are derived on save: the room under the middle of that bar (null = none).

## Areas (outside)

`areas`: `[{ id, name, kind, shape, layout, outline?, roofed?, species? }]`, a labelled footprint that is not part of the room graph. `shape` is `rect` or `ellipse`, `layout` as for rooms. `roofed` (true when present): the area has a roof (carport, pergola). `species` (optional text, up to 40 characters, used for `tree` areas): the kind of tree, for example `Eucalyptus (gum)` or `Jacaranda`.

- `outline`: optional shape for a rectangular area that is not a rectangle (L, U, T, bays), exactly as for rooms: corners `[[x, y], ...]` in metres from the top-left corner of `layout`, clockwise on the plan, 90 degree corners only, no holes; `layout` stays the bounding box. An area with an outline has `shape` `rect`. Only areas of the same kind and the same roofed state can be merged into one shaped area. A `tree` is an ellipse whose centre is the trunk: its canopy may overhang rooms, only the centre must lie outside rooms.
- `elevation`: optional, metres above the floor baseline (a raised deck), 0..10, default 0 (absent).

## Entities

`entityPlacements`: sensors, lights, contacts and so on, placed on the plan. `{ id, type, name?, haEntityId?, roomId | areaId | connectorId | objectId, side?, position?, height?, facingDegrees?, fieldOfViewDegrees?, range? }`

- Exactly one anchor: `roomId`, `areaId`, `connectorId` or `objectId` (connector entities have no `position`; `side` `A` or `B` says which room of the pair). `objectId` puts the entity ON an object (see below) and only fits the types marked in the last column of the table.
- `position`: `[x, y]` metres. With `entitySettings.coordinates` = `room` (default) it is measured from the top-left corner of the room or area, otherwise from the plan origin. With `objectId` it is measured from the CENTRE of the object in the object's own frame (x along its width, y along its depth, turned with its `facingDegrees`), so the entity follows the object; `height` then defaults to the top of the object. `entitySettings.gridStep` is the placement grid.
- `height`: metres above the floor. `haEntityId`: the Home Assistant entity this placement stands for.
- `facingDegrees`, `fieldOfViewDegrees` (full opening angle), `range` (metres): for directional types only.
- `role` (optional, connector entities of the types `door-contact` and `window-contact`): `open` (the default, written as absent) or `tilt`. A connector can carry any number of entities, also of the same type and role (two `open` contacts, a contact next to a lock and a blind, a future glass-break sensor); a tilting window or a tilt-and-turn door typically has an `open` and a `tilt` contact. A `tilt` contact needs a window of type `tilt` or `tilt-turn`, or a door with `door.tilt`. Checks: `invalid-option` (unknown role), `role-mismatch`.

## Objects (appliances, furniture)

`objects`: `[{ id, type, name?, roomId | areaId, position, facingDegrees?, width?, depth?, height?, elevation?, category? }]`: things with a footprint, such as a refrigerator or a sofa.

- Exactly one host: `roomId` or `areaId`. `position`: `[x, y]` metres, the CENTRE of the footprint measured from the top-left corner of the room or area (x right, y down).
- `facingDegrees`: the direction the front points to, clockwise from up (0 = up on the plan, 90 = right), the same convention as for entities. `width` runs across the front, `depth` from front to back; at facing 0 the width is along x.
- `height` and `elevation` (height of the underside above the floor, for wall-mounted things) are in metres. `category` is free text (lower case, 1 to 32 characters): `appliance` and `furniture` are built in, others such as `sanitary` or `outdoor` can be added in the editor; a reader may hide whole categories (for example furniture).
- `type` is a built-in type (table below) or an `id` from `objectTypes`: `[{ id, label, category, width, depth, height, elevation?, clearance? }]`. A custom type with the id of a built-in one replaces it. `clearance` is the free space needed in front (metres).
- Width, depth, height, elevation, category and name are written explicitly on save; they default to the type.
- Deleting a room or area deletes its objects, and deleting an object deletes the entities on it.

## What the editor checks before saving

Errors (the file would be wrong): `duplicate-room`, `duplicate-connector`, `duplicate-relationship`, `duplicate-area`, `duplicate-object` (repeated ids), `no-layout`, `unknown-floor`, `connector-room`, `dangling-connector`, `dangling-alignment`, `stairs-floors`, `stairs-size`, `relationship-invalid`, `dangling-object`, `dangling-entity-object` (an entity sits on an object that does not exist), `room-outline-invalid` (not a valid shape with 90 degree corners), `room-outline-bounds` (the outline does not span the width x height of the room), `connector-off-wall`.
Warnings (the file is usable): `stairs-room`, `relationship-broken` (the pair is not aligned), `entity-*` (the entity checks, for example low coverage, no door contact, no motion sensor, `outside-object` for a position beyond the footprint of its object), `area-*`, `height-*` (`height-elevation-range`: a room or area outside 0..10 m; `height-window-above-wall`; `height-shared-wall-height`: the two sides of a shared wall differ), `object-*` (`unknown-type`, `outside`, `overlap`, `blocks-door`, `blocks-clearance`, `too-high`; only doors count for `blocks-door`, open passages are free; `blocks-clearance` = another object of the same room or area stands in the free zone in front of the object, e.g. the door swing of a refrigerator).
