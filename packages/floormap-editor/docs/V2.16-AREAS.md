# Outside areas (Site mode)

Deck, driveway, garden / plot, pond and path as flat, labelled footprints around the house. They are **not** part of the room graph: no connectors, no solvers, no mapper, no overlap blocking. The premise is the editor's: a first model, not a digital twin, so an area is a name, a kind and a rectangle or ellipse. Entities (cameras, lights, motion sensors, ...) can sit in areas.

## Data (optional, additive: `schemaVersion` stays `2.14`, files without `areas` are unchanged)
```json
"areas": [
  { "id": "deck", "name": "Deck", "kind": "deck", "shape": "rect", "layout": { "x": 12, "y": 2, "width": 4, "height": 3 }, "roofed": true },
  { "id": "pond", "name": "Pond", "kind": "pond", "shape": "ellipse", "layout": { "x": 3, "y": 12, "width": 2.5, "height": 1.8 } }
]
```
- Plan coordinates in metres (x right, y down), axis-aligned. `shape`: `rect` or `ellipse` (inside `layout`). Minimum size 0.5 m.
- `kind` (`areaKinds()` in `src/areas.ts`): `deck` (4 x 3), `driveway` (6 x 3), `garden` (10 x 8, the plot: may surround the house), `pond` (ellipse 2.5 x 1.8), `path` (4 x 1), `other` (3 x 3). The kind sets the colour and the default size / shape.
- `roofed` (optional, `true` = carport / pergola, drawn hatched). *Save graph* writes `shape` and `roofed` explicitly and rounds positions to 4 decimals.
- Not planned: polygons, rotation, terrain, roads, trees, heights. Polygons would arrive together with polygon rooms (same vertex model).

## Site mode (`Floor plan | Site | Entities`)
- The floor plan is read-only (rooms dimmed). Areas are drawn pale **below the rooms in all three modes**, clickable only in Site mode. **Fit** includes areas.
- **Add:** pick a kind in the palette, then click (default size, centred on the click, grid snapped) or drag a rectangle. Shift keeps the kind armed, Alt = free position, Esc cancels.
- **Edit:** click an area to select it (the smallest area under the pointer; a click inside a room is background), drag to move, corner handles to resize, Delete key or the trash icon removes it. Inspector: name, kind, shape, X, Y, W, H, roofed, entity count, warnings. One undo step per gesture or field edit.
- An area that overlaps a room (not for gardens) gets a dashed red outline and a warning; nothing is blocked.

## Entities in areas (`areaId`)
- An entity is anchored to exactly one of `roomId`, `areaId` or `connectorId`. `position` is relative to the area's top-left corner, like for rooms. The world point is the area corner plus the position.
- Allowed types (`outdoor: true` in the catalogue): light, motion sensor, camera, environment sensor, water leak sensor. Others stay in rooms (the validation flags a mismatch).
- Placing (entity mode): click inside a room, else inside an area (ellipses honour their curve). Order under a point: rooms (smallest), then areas (smallest), then the hidden `Outside` room. Indoor-only types ignore areas. Dragging, group moves and paste re-parent across rooms and areas; align and distribute keep every entity in its own room or area.
- Moving an area moves its entities with it; resizing scales them (`entitySettings.resize`, proportional or anchor, exactly as for rooms). **Deleting an area removes its entities** (status: "N entities removed", undo restores).
- `entitySettings.coordinates: "plan"` converts area entities too. Coverage hints (rooms without motion sensor, doors without contact) only concern rooms and doors.

## Code and tests
`src/areas.ts` (pure: `areaKinds`, `addArea`, `updateArea`, `removeArea`, `areaAt`, `validateAreas`, `fillAreaDefaults`), `src/entities.ts` (`entityHost`, `entityHostAt`, area-aware add / move / paste / align / validate / sync), `src/editor-site.ts` (CSS / HTML / JS of the mode) plus a few hooks in `src/editor.ts`: the floor-plan `pointerdown` returns early outside plan mode, areas are inserted below the rooms in a render wrapper, `fit()` is replaced by a version that includes areas.
