# Non-rectangular rooms (v2.18): rectilinear outlines

Goal: rooms with 90 degree corners only (L, U, T, bays, notches), not just rectangles. No diagonal or curved walls, no holes (a pillar is an object, a shaft a separate room).

## Model (decided)
- A room keeps `layout` `{x, y, width, height}` and it stays the **bounding box**. An optional `outline` lists the corners relative to the layout's top-left, clockwise on screen (x right, y down), edges alternating horizontal / vertical, no collinear corners, starting at the top-left-most corner. No `outline` = rectangle, so every existing file, the 3D viewer and the building card keep working (a reader that ignores `outline` sees the bounding box).
- **Connectors** keep `side` (the direction the wall faces) and `offset`, but the offset is measured from the bounding-box edge. `side` + `offset` names the wall segment (`outlineWallAt`), with no edge indices that go stale when the shape is edited. Correction found in use: two walls facing the same way CAN cover the same offset (the outer wall and the notch wall of an L, both arms of a U), so a connector may carry `wallAt` (the wall's coordinate from the bounding box origin); without it the outermost wall is meant, so a connector on an outer wall never jumps into a notch. `reshapeRoom` keeps the wall a connector sits on and writes `wallAt` only when it is not the outermost one. A connector whose wall disappears is reported.
- Objects, entities, areas and stairs keep positions relative to the bounding-box corner; only the "is it inside" checks change from rectangle to polygon (`outlineHasRect`, `outlinePoint`).
- Areas (decks, ponds) can reuse the same outline later.

## Engine (phase 1, done): `src/shape.ts`
Pure, deterministic, embedded into the page like the other modules (`embed.ts`). All work happens on a **compressed grid** (the sorted x / y coordinates of the corners; a cell is inside when its centre is), so booleans, overlap and containment are exact without general polygon clipping. Coordinates are rounded to 1e-6.

| Function | Purpose |
|---|---|
| `outlineFromRect`, `outlineBounds`, `outlineArea` | basics |
| `outlineNormalize` | canonical form (rounded, collinear / duplicate corners removed, clockwise, top-left start) |
| `outlineIssues` | validation codes: `points`, `diagonal`, `alternate`, `self-intersect`, `orientation` |
| `outlinePoint`, `outlineHasRect` | containment (boundary counts as inside) |
| `outlineOverlapArea` | shared area of two outlines (for overlap blocking) |
| `outlineCombine(a, b, op)` | `union` / `subtract` / `intersect` -> `{ outlines, holes }`; a room needs exactly one outline and no hole; parts touching only at a corner are separate outlines |
| `outlineWalls`, `outlineWallAt` | wall segments (`side`, `at`, `from`, `to`) and the wall of a connector (`side`, `along`) |
| `outlineGrid` | the shared grid helper |
| `outlineLabelRect` | largest rectangle inside (label position) |

Tests: `test/shape.test.ts` (hand-computed L and U cases, 500 random unions / differences / intersections against an independent cell raster: area, every cell centre, containment, overlap, perimeter, canonical form; embedded source matches Node).

## How rooms get their shape (next phases)
1. **Pull / push from a rectangle (primary):** a handle on a wall turns a segment into a notch or bump (union / subtract of a rectangle); the segment ends slide along the wall; cutting a corner gives an L.
2. **Merge / split (second):** merge two touching rooms (removes the shared wall, re-anchors connectors, objects, entities, stairs and relationships) and split along an axis-aligned line.
3. **Wall by wall:** only as an advanced redraw, later.

## Phase 2 (done): file and drawing
- `Room.outline` (core.ts) is read as it is (unknown keys survive), `migrate` writes it canonical, drops a plain rectangle and **size-locks a real shape** (`layout.sizeLocked = true`), so resize handles, the Width / Height fields and the wall solver leave the shape alone; the Lock size checkbox is ticked and disabled. `fillDefaults` (Save graph) does the same normalisation. Invalid outlines are kept so the contract can report them.
- Contract: errors `room-outline-invalid`, `room-outline-bounds` (the outline must span exactly the layout's width x height from (0, 0)), `connector-off-wall`; warning `connector-inner-wall`.
- Drawing (`src/editor-shapes.ts`, used by `render`): a room with a valid outline is an SVG `<path>` with the same CSS classes (selection, locks, hit testing, Gap view scaling unchanged); rectangles produce the identical `<rect>` as before; the label sits in the middle of the largest rectangle inside (`outlineLabelRect`).
- `docs/FILE-FORMAT.md` describes `outline` and the new checks (regenerate with `npm run build && npm run docs:format`).
- Tests: `test/shape-rooms.test.ts` (load, save, contract), `scripts/browser-smoke-shapes.mjs` (path, label, locked size, move, saved outline).
- **Example:** `examples/house-with-shapes.json` (6 rooms: L living room, bay study, T hall, U bedroom, plain kitchen and bathroom; 6 green connections, objects and entities, no contract warnings; checked by `test/shape-example.test.ts`). Load it in the editor, or build a page with `node dist/examples/generate.js examples/house-with-shapes.json examples/house-with-shapes.html`. All connectors are on walls that lie on the bounding boxes, and nothing stands in a notch (see the limits below).
- **Known limits until the next phases:** overlap blocking in the planners, the Drag walls strips and Close gaps / Fit still use the **bounding box**. Rooms with a shape can have neighbours in a notch (phase 4), but the planners' overlap check (Block overlaps in the Slide modes, Drag walls) still compares bounding boxes, so moving a room into a notch in those modes is refused; Free mode and loading are not affected.

## Phase 3 (done): objects, entities and stairs respect the shape
- **Hosts:** a room with an outline is a host with that shape. `objectHostAt` / `entityHostAt` do not return it for a point in a notch (so a click in the notch places nothing and a drop there goes to the room under it, if any); `objectHost` / `entityHost` carry the `outline`.
- **Objects:** `objectClamp` moves an object that does not fit to the nearest place where its footprint bounds lie inside the shape (so a dragged object slides along the notch walls instead of entering them); `objectSnap` snaps to the wall segments of the shape (left / right walls for the x edges, top / bottom for the y edges, only walls that face the footprint); `validateObjects` reports `outside` ("Reaches outside the shape of its room") for a footprint that touches a notch.
- **Entities:** `entityClamp` keeps a room-relative point inside the shape (nearest wall point; a tie goes to the smaller y); used by add, move, update, group move, paste and align. `validateEntities` reports `outside-room` for a position in a notch. Entities on objects are unchanged.
- **Stairs:** `stairsHost` does not accept a bar that lies in a notch.
- **Areas:** unchanged (they are not hosted by rooms).
- Tests: `test/shape-hosts.test.ts` (L room with hand-computed positions), a notch scenario in `scripts/browser-smoke-shapes.mjs`.

## Phase 4 (done): joints per wall segment
- A connector sits on a wall **segment**: for a room with an outline it is the segment facing the connector's `side` at its `offset` (measured from the bounding box edge, `outlineWallAt`); for a rectangle nothing changes (bit-identical results). The connector point is on that segment (`point`, `pt`, `dpoint`), the contract no longer warns about inner walls (`connector-inner-wall` is gone).
- `deriveJoints`: gap, shared part, slide range, `fixedOpening` and the opening use the two wall segments, so a rectangle sitting in the notch of an L is green on both inner walls and slides within the segment. The editor's own `touch` / `aligned` / `setWorld` (core and page) do the same, so the parity between joint status and the green / red connector check holds.
- Dragging a connector keeps it on its wall (`portTarget`, `setWorld`, `norm` clamp to the segment); the teal slide overlay of a joint is drawn on the segment.
- Rooms with a shape are rigid (size-locked), so Free and Slide moves carry them as a whole.
- Tests: `test/shape-joints.test.ts` (L with a rectangle in the notch: gap 0, shared parts, slide ranges -1..1 / -0.55..0.55, broken cases, `setWorld` clamping, embedded copy matches Node), a scenario in `scripts/browser-smoke-shapes.mjs`.

## Phase 5 (done): the Shape tool
- **Tool > Shape (pull / push walls)** (toolbar button "Shape", or the Tool select in the classic layout): every wall segment of every room gets a grab strip, like Drag walls.
  - **Drag a segment** along its normal to move it: a rectangle is resized, an L gets a longer arm, a notch wall moved out fills the notch (collinear walls that line up merge, so a room that becomes a rectangle again loses its `outline`).
  - **Shift + drag** pulls a **bump** (outwards) or **notch** (inwards) out of the wall at the pointer; its width is the *Bump* field in the toolbar (default 1 m), it is clamped to the wall, so a notch that reaches a wall end cuts a corner (an L).
  - Planned from the graph at the start of the drag (dragging back returns exactly); an impossible result keeps the last possible one and the status line says why; one undo step per gesture.
- **Feedback:** with Shift held, the part of the wall under the pointer that a bump or notch would cover is shown in red (like a connector); while dragging, the walls that change (moved, stretched, new) are labelled with their length in metres.
- **Moving rooms next to shapes:** the Slide modes' *Block overlaps* (`planMove`) measures overlaps on the real shapes, so a room can be moved into the notch of an L-shaped neighbour (Drag walls and Close gaps / Fit still use bounding boxes).
- **Rules:** a wall must stay at least 0.3 m long, no part of the room (and no notch) may be thinner than 0.3 m (`outlineThin`), the shape must stay one piece without holes or crossings, a bump / notch is at least 0.2 m deep. *Block overlaps* (Settings) is measured on the real shapes (a neighbour in a notch is no overlap). A position-locked room cannot change in a way that moves its top-left corner. **A wall (or the part of it the bump covers) shared with ONE other room moves for both rooms** (`reshapeWithPartner`): a room counts as sharing it when its facing wall lies on that stretch with a positive shared length, with or without a door (the `Outside` room never follows; a detached connection does not matter). The neighbour loses what the room gains and gains what it gives up next to its wall (so it may become a shaped room too), doors and windows on that stretch of both walls move with it (same place along the wall, pairs stay green), the status line says "<neighbour> changed with it", one undo step. Refused with a message when the stretch is shared with several rooms (hold Alt to move only this room), connected to the Outside room, the neighbour is size-locked (a rectangle with the lock) or position-locked and its corner would move, would be cut apart or get a wall shorter / a part thinner than 0.3 m, a door or window would be cut off, or (Block overlaps) either room would newly overlap a third room. Alt + drag moves only the dragged room (`alone`): that works while no connection is attached to the stretch, and Block overlaps then stops the move at the neighbour.
- **What follows the change:** the layout becomes the new bounding box (the room's corner may move), connector offsets are re-based so connectors stay on their walls, objects and entities of the room keep their place on the floor, a real shape is size-locked.
- Code: `outlineMoveWall`, `outlineBump` (shape.ts), `shapeOfRoom`, `shapeWallPartner`, `reshapeRoom`, `moveRoomWall`, `pullRoomWall` (room-shape.ts, pure, embedded), `src/editor-shape-tool.ts` (strips, drag), hooks in `editor-core-pointer.ts`, `editor-shell.ts`, `editor-core-click.ts`. Loading a file in the editor also normalises and locks shaped rooms.
- Tests: `test/room-shape.test.ts` (hand-computed outlines, bumps, notches, refusals, re-basing of connectors / objects / entities, overlap, locks, embedded copy), a Shape-tool scenario in `scripts/browser-smoke-shapes.mjs`.
