# CLAUDE.md - floormap-editor 3.0 beta (package version 3.0.0-beta.1; the graph schemaVersion is still 2.14)

Guidance for Claude Code (or any assistant) working in this package. Full background: `docs/HANDOFF.md`.

## What this is
The editor that turns a room graph (rooms + connectors + relationships, **no coordinates**, produced by the `room-graph` editor) into a floor plan, and then lets the user refine it by moving rooms and dragging walls. Output is a self-contained HTML file generated by `editorHtml(raw)` in `src/editor.ts`.

## Ground rules
- **Scope:** change only this package (`packages/floormap-editor`). Do not touch `floormap-structure`, `room-graph`, `shared` (read-only fixtures) or the root files unless asked.
- **Do not change existing editing behaviour** unless the user confirmed it. Move mode **Free** and Tool **Move rooms** must stay exactly as they were in v2.14. New behaviour goes behind a switch.
- Precision is not the goal: this is a first model that the user refines by dragging. Prefer robust and predictable over clever.
- Ask before schema changes, before deleting behaviour, and before editing a regression test's expectation. (One was changed on purpose: the label "Lock size and position" became "Lock position" + "Lock size".)

## Commands (run in this folder)
```bash
npm install
npm test                                   # tsc build + node --test (every test/*.test.ts)
node dist/examples/generate.js ../shared/reference-home-connectors.json examples/room-graph_mapping.html
npm i -D jsdom && node scripts/browser-smoke.mjs   # optional: drives the generated editor in a fake DOM
```
`npm test` must stay green. After changing `src/editor.ts`, also run the smoke script: unit tests cannot catch broken browser glue.

## How the browser code works (important)
- Pure modules are embedded into the HTML with `fn.toString()` in this order: `mapLayout, createHistory, deriveJoints, planMove, planWall, planCorner, planAlign, planClose, planFit, doorGeometry, doorAngle, mirrorDoor, fillDefaults, connectRooms, addRoom, removeRoom, removeConnector`. Rules for these functions:
  - no imports of values and no outer-scope references, except sibling globals: `planMove` and `planWall` call `deriveJoints`, `planCorner` / `planAlign` call `planWall` + `deriveJoints`, `addRoom` calls `connectRooms`;
  - keep helpers *inside* the function; types may live outside (erased by tsc);
  - build with `tsc` (not esbuild with keepNames, which injects helpers that break `toString`).
- Tests slice the embedded source between `function mapLayout(` and `function applyMap(` and evaluate it, so keep that order and those names.
- `editor.ts` is dense, minified-style JS inside a template literal (plain quotes; `\u2195` style escapes are intentional). **Edit it with small exact-substring replacements that match exactly once**, never by reformatting. Show a diff before and after.
- Drag handling: `active` holds the gesture; `pointerdown` snapshots `g0` (graph) and `j0` (joints) for the planners; `pointermove` recomputes from the snapshot (so dragging back returns exactly); `end()` records one undo step via `rec(before)` only if the graph changed. **Every move must be stateless**: `applyPlan` restores all connectors from `g0` before applying the plan (stale offsets from earlier pointer moves once left pairs 0.2 m apart); Free / Alt drags use `holdPairs`, which recomputes pairs that were green at the start from the start snapshot. Never re-align connectors cumulatively per pointer move (that made drags jump). The one deliberate exception to "planned from the start": a room without attached joints is swept from its current position (`from`), so it can be dragged around obstacles.
- Planner options set by the editor: `noOverlap`, `glueTouching` (touching rooms without a relationship follow a dragged wall), `alignments` (wall alignment groups as collinear constraints), `ignoreIds` (the hidden `Outside` room never blocks, is never glued and does not count as part of the floor plan), `blockWholePlan` (refuse a move that shifts the largest attached group, i.e. the whole floor plan), `slideAlong`.

## Data model
- Metres, x right, **y down**. Layout = `{x, y, width, height, locked?, positionLocked?, sizeLocked?}`; grid 0.2 m (0.1 / 0.05 selectable).
- Locks: `positionLocked` = top-left corner fixed; `sizeLocked` = width/height fixed. Old `locked: true` means both; explicit flags win; the UI writes `locked: true` only when both are set.
- Connector offset = metres from the wall start (left for top/bottom walls, top for left/right walls), clamped to [0.05, length - 0.05] by `norm`. `position` (0..1) is legacy.
- `graph.joints` (optional) = `[{ relationshipId, state: 'attached' | 'detached' }]`; absent means everything attached.
- The room named `Outside` is a normal room in the model but is hidden when drawing and in Fit.

## Invariants (tests enforce these; keep them)
- **Joint status mirrors the editor's own `aligned()`**: walls touch (<= 0.08 m, positive shared part) and connector points are within 0.2 m. A parity test compares counts over 300 random edits. "Narrow" is informational and never changes status.
- Everything is deterministic: same input gives same output, independent of room/relationship order. No `Math.random`, no `Date` in planners or the mapper.
- Planners never move locked rooms, never lose a joint that was attached at the start of the drag, and with `noOverlap` never create a new overlap (except with ignored hidden rooms). They sweep the drag in grid steps and stop at the last feasible step (no tunnelling); a drag distance that is not a grid multiple ends exactly on target.
- Opening points: both connectors of an attached pair always get the same world position; when both rooms move together along the wall the opening travels with them, when one slides it stays put (pushed inside the shared part if needed).
- Alignment groups: only walls that are at the same level now (within 1 cm) are constrained; "Add alignment" / "Re-align" snap to the first selected room (the reference); Free mode never changes or removes a group (an unlevel group is listed as Inactive).
- Use `+ 0` after rounding to avoid `-0`; use `EPS` (1e-6) in geometry comparisons (a 0.9 m wall once measured 0.8999999 m and broke a joint).
- Undo/redo: one step per finished gesture; loading a file clears history.

## Testing conventions
- Prefer hand-computed expectations on tiny scenes (state the arithmetic in the test name) plus seeded property tests on the reference home (LCG `seed * 1664525 + 1013904223`).
- Every new interaction gets: a pure-module test, an "embedded source evaluates and matches Node" test, and a scenario in `scripts/browser-smoke.mjs`.
- Verify what is on disk, not what you meant to write: after editing, rebuild and run the suite from the real files.
- **Files must be written to the user's disk** (Filesystem tools), not to the assistant's sandbox; check with a directory listing after creating files.
